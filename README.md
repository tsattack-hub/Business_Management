# 구매설치 사업관리

구매설치사업을 처음부터 끝까지 관리하는 도구입니다. 하는 일은 세 가지입니다.

1. **단계별로 무엇을 해야 하는지** 알려주고 진행 상태를 관리합니다
2. **각 단계에서 작성할 서류**를 알려주고, 채울 수 있는 부분을 채운 **틀을 만들어 줍니다**
3. **각 단계에서 조심할 것**을 알려줍니다

---

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

브라우저가 열리지 않으면 `http://localhost:8501`.

## 화면

좌측에 사업 정보를 넣고 **저장**하면, 본문에 6단계가 펼쳐집니다.

```
판정        구매설치 · 설치비중 27.1%
진행        0 / 39 태스크

1. 설계 — 규격서부터 계약의뢰까지     0/15 완료 · 서류 5종
     이 단계에서 조심할 것    ← 실제 지적 사례만 추려서 보여줍니다
     할 일                  ← 체크하면 진행률에 반영됩니다
     작성할 서류             ← [틀 만들기] → [내려받기]
2. 입찰 · 계약                        0/4  완료 · 서류 1종
3. 착수 · 제작                        0/5  완료 · 서류 2종
4. 납품 · 설치                        0/5  완료 · 서류 2종
5. 준공 · 정산                        0/6  완료 · 서류 2종
6. 하자관리                           0/4  완료 · 서류 1종
```

### 사업 조건에 따라 절차가 달라집니다

좌측 **사업 조건**에서 체크한 것만 절차에 나타납니다.
CCTV가 아니면 행정예고가 사라지고, 관급자재가 없으면 별도 구매 트랙이 빠집니다.
전체 52개 태스크 중 실제로 필요한 것만 남습니다.

### 계약유형 판정

설계금액 세 칸(재료비 · 직접노무비 · 경비)을 넣으면 자동으로 판정합니다.

```
설치비중 = (직접노무비 + 경비) ÷ 전체 설계금액
  50% 이상 → 공사계약 (이 도구의 범위 밖, 진행이 멈춥니다)
  50% 미만 → 구매설치
```

45~55% 구간이면 경계값 경고가 뜹니다. 이 판정 하나가 원가계산 비목 ·
낙찰방법 · 완료절차 · 하자담보를 전부 결정하므로, 근거를 문서로 남겨야 합니다.
`물품·공사 혼합계약 유형 판정 근거표`가 그 용도입니다.

## 만들어 주는 서류 13종

| 단계 | 서류 | 형식 |
|---|---|---|
| 1 설계 | 물품·공사 혼합계약 유형 판정 근거표 | xlsx |
| | 구매규격 사전공개 의뢰 | hwpx |
| | 시행계획보고 | hwpx |
| | 시행결의서 | hwpx |
| | 계약의뢰서 | hwpx |
| 2 입찰·계약 | 청렴서한문 | hwpx |
| 3 착수·제작 | 주요기자재 공급원 승인 알림 | hwpx |
| | 선금지급 적정성 검토결과 | hwpx |
| 4 납품·설치 | 검사조서 | hwpx |
| | 검수조서 | hwpx |
| 5 준공·정산 | 준공검사조서 | hwpx |
| | 준공정산 내역서 | xlsx |
| 6 하자관리 | 하자검사 계획보고 | hwpx |

### 어디까지 채워 주는가

사업 정보로 채울 수 있는 것은 채웁니다 — 사업명, 공항, 추정가격, 설계금액,
계약유형, 설치비중, 조달트랙, 낙찰방법, 이행기간, 작성일.

**사람이 판단해야 하는 곳은 「( 작성 필요 )」로 비워 둡니다.**
그럴듯하게 지어내지 않습니다. 사업 목적, 필요성, 계약방법 선택 사유 같은 것들입니다.

### 두 서류는 계산까지 합니다

**판정 근거표** — 비목별 귀속과 설치비중 계산이 표로 들어갑니다.
감사에서 계약방법 선택 근거를 물으면 이 한 장으로 답이 됩니다.

**준공정산 내역서** — 노란 셀에 보험료 정산액만 넣으면
일반관리비 · 이윤 · 부가세가 자동으로 연동 계산됩니다.
「보험료만 정산하고 일반관리비 · 이윤 · 부가세를 정산하지 않음」이
실제 지적 사례라, 그 실수가 구조적으로 나오지 않게 만들었습니다.

## 구매규격서 초안 생성

품목군을 고르면 조항 라이브러리에서 해당 조항을 골라 규격서를 조립합니다.

```
품목군      영상감시장치 (CCTV)
조항        17개   (표준 12 · 관행 5)
채울 빈칸    11개
특정회사 규격 0건
```

### 세 층으로 나뉩니다

| 층 | 처리 |
|---|---|
| 일반사항 · 제출물 · 검사검수 · 하자 | 완전 자동 |
| 특기시방 (기술기준) | 품목군 조항에서 조립 |
| 수치 규격 (해상도 · 용량 · 성능) | 화면에서 입력. 안 넣으면 「 」로 남습니다 |

지어내지 않습니다. 사업 목적이나 연동 대상처럼 사람이 판단할 것은 빈칸으로 두고,
어떤 빈칸이 몇 개 남았는지 목록으로 보여줍니다.

### 특정회사 규격을 함께 잡습니다

생성기와 검증기를 붙여 둔 이유가 있습니다. 다른 기관 규격서에서 조항을 가져오면
**그 기관 사정에 맞춘 조건이 딸려옵니다.** 특정 제조사 모델번호, 그 기관만의 인증
요구 같은 것들이요. 그대로 쓰면 부당한 입찰 제한이 되고 감사 지적 사유입니다.

조립 직후 본문을 스캔해서 상표명·모델번호·유도표현을 잡아냅니다.

```
상표: '한화비전'                    ← 성능 수치로 바꿔 쓸 것
모델번호로 보이는 문자열: 'XNO-8080R'
특정 제조사 유도 표현: '정품 제품'
```

`IEEE 802.3af`, `H.265`, `IP66` 같은 기술 표준은 오탐하지 않습니다.
「동등 이상」 문구가 붙어 있으면 표시하되, **그것만으로는 면책되지 않는다**고 안내합니다.

### 조항을 늘리려면

`docs/spec_clauses.yaml` 하나만 고치면 됩니다.

```yaml
품목군:
  - id: CCTV
    조항: [SPEC-CCTV-01, ...]
    규격항목:
      - {key: 해상도, 힌트: "예) 200만 화소 이상", 필수: true}

품목조항:
  - id: SPEC-CCTV-01
    절: 2
    제목: 네트워크 카메라
    출처: 관행          # 표준 / 관행 / 수집
    본문: |
      가. 해상도 : [[해상도]] 이상
```

`[[해상도]]`는 규격항목의 `key`와 이름이 같으면 입력값으로 채워지고,
없으면 빈칸으로 남습니다. `[[ 연동 대상 ]]`처럼 안내문을 쓰면 항상 빈칸입니다.

출처는 세 가지로 구분합니다.

- `표준` — 법령·계약예규에서 온 것. 그대로 써도 안전
- `관행` — 공공 발주에서 통용되는 문구. 사업에 맞는지 확인
- `수집` — 나라장터 사전규격에서 추출한 것. **반드시 검토 후 사용**

## 나라장터 규격서 수집 (조달청 API)

`scripts/collect.py` 로 사전규격을 조회하고 규격서에서 조항을 추출합니다.

### 0. 인증키 발급

공공데이터포털에서 **조달청_나라장터 사전규격정보서비스** 활용신청 (무료).

- https://www.data.go.kr/data/15129437/openapi.do
- 승인 직후에는 1시간 정도 반영이 걸릴 수 있습니다

```powershell
$env:G2B_KEY="발급받은키"
```

### 1. probe — 최초 1회 반드시

```powershell
python scripts/collect.py probe
```

**응답 필드명이 확정되지 않았습니다.** 공공데이터포털이 자동 접근을 막아
활용명세서를 기계적으로 확인할 수 없었습니다. `docs/g2b_api.yaml` 의
`candidates` 는 조달청 API 작명 규칙으로 추정한 후보 목록입니다.

probe 는 실제 응답의 키 목록과 매핑 결과를 보여줍니다.

```
필드 매핑 결과
  OK   등록번호     <- bfSpecRgstNo
  ??   납품기한     <- 찾지 못함

응답에는 있으나 우리가 안 쓰는 키 1개
     dlvrTmlmtDt              = 20260630
```

`??` 가 나오면 아래 목록에서 해당 이름을 골라
`docs/g2b_api.yaml` 의 `fields.<이름>.candidates` 맨 앞에 추가하십시오.

### 2. list — 목록만 조회

파일을 내려받지 않으므로 부하가 거의 없습니다. 먼저 이걸로 규모를 보십시오.

```powershell
python scripts/collect.py list --days 90 --group CCTV
python scripts/collect.py list --days 180 --group CCTV --only-preferred
```

`--only-preferred` 는 공항공사·철도공사 등 유사 발주기관만 남깁니다
(`docs/g2b_api.yaml` 의 `filters.선호기관`).

### 3. harvest — 규격서 수집 + 조항 추출

```powershell
python scripts/collect.py harvest --days 90 --group CCTV --max 30
```

- 기본 상한 **50건**. 요청 간 1.5초 대기합니다. 이 값을 낮추지 마십시오
- 파일명에 `규격`·`시방`·`과업`·`사양` 이 있는 것만 받습니다.
  `공고문`·`유의서`·`계약서`·`서식` 은 건너뜁니다
- HWP · HWPX · PDF · DOCX 에서 텍스트를 뽑아 절/조항 단위로 분해합니다

레거시 `.hwp` 도 읽습니다 (OLE 컨테이너에서 BodyText 레코드를 직접 파싱).

### 4. export — 라이브러리 형태로 내보내기

```powershell
python scripts/collect.py export
```

`수집결과/수집조항.yaml` 이 만들어집니다. 모든 조항에 `출처: 수집` 과
`수집출처`(기관 · 사전규격번호 · 파일)가 붙습니다.

### 그대로 쓰지 마십시오

다른 기관 규격서에는 **그 기관 사정에 맞춘 조건**이 섞여 있습니다.
특정 제조사 모델, 그 기관만의 인증 요구, 지역 조건 같은 것들이요.
그대로 옮기면 부당한 입찰 제한이 되고 감사 지적 사유입니다.

검토해서 쓸 것만 `docs/spec_clauses.yaml` 로 옮기고,
그때 `출처` 를 `수집` → `관행` 또는 `표준` 으로 올리십시오.
옮긴 조항은 규격서 생성 시 브랜드 스캔을 자동으로 받습니다.

## 고치는 방법

**코드를 건드릴 일은 거의 없습니다.**

| 무엇을 바꾸려면 | 어느 파일을 |
|---|---|
| 금액 기준, 일상감사 대상 | `rules/01_기준금액.yaml`, `rules/07_기준금액_구매설치.yaml` |
| 단계와 할 일 목록 | `rules/06_절차템플릿_구매설치.yaml` |
| 주의사항 문구 | `rules/04_감사검증룰.yaml`, `rules/08_감사검증룰_구매설치.yaml` |
| **서류 틀 내용** | `docs/templates.yaml` |
| **규격서 조항** | `docs/spec_clauses.yaml` |
| 공휴일 | `data/holidays.yaml` |

서류 틀은 이런 모양입니다. 블록을 늘리거나 문구를 고치면 바로 반영됩니다.

```yaml
- id: DOC-시행계획보고
  명칭: 시행계획보고
  format: hwpx
  단계: P1
  태스크: T-P1-140
  blocks:
    - {type: heading, level: 1, text: "3. 사업 추진의 합법성 및 필요성"}
    - {type: fillin, label: "합법성 및 필요성", hint: "근거 법령·규정과 필요한 이유"}
```

블록 타입은 `heading` · `paragraph` · `bullets` · `table` · `fillin` · `page_break` 여섯 개입니다.
치환자는 `{사업명}` `{추정가격}` `{설치비중}` 처럼 중괄호로 씁니다.

바꾼 뒤에는 회귀 테스트를 한 번 돌리세요.

```bash
python tests/run_tests.py       # 147건
```

### 선택 기능 — 내역서 검증

내역서의 소계 · 합계를 검산하고 수량산출서와 대조하는 화면이 따로 있습니다.
`extra/1_내역서_검증.py` 를 `pages/` 폴더로 옮기면 좌측 상단에 나타납니다.

```bash
mkdir -p pages && cp extra/1_내역서_검증.py pages/
```

`sample/sample_내역서_오류.xlsx` 로 시험해 볼 수 있습니다. 심어 둔 오류 6종
(행 금액 · 합계 열 · 소계 · SUM 범위 누락 · 하드코딩 · 총계)을 전부 잡습니다.
지금은 본 흐름과 분리해 두었습니다.
